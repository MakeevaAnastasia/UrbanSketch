# UrbanSketch.pro — спринт 1 (19–30 октября 2026)

**Статус: проектный комплект спринта 1.** Основан на исходном ТЗ и итоговом плане-графике заказчиков. Финальные технические решения и вопросы в `docs/06_open_questions.md` требуют согласования.

## Состав

- `docs/01_requirements.md` — требования первой версии и границы проекта.
- `docs/02_user_scenarios.md` — пользовательские сценарии и последовательность экранов.
- `docs/03_data_dictionary.md` — входные ТЭП и финансовые параметры.
- `docs/04_financial_rules.md` — формулы, бизнес-правила и эталонный пример.
- `docs/05_architecture.md` — архитектура, зависимости и технологические решения.
- `docs/06_open_questions.md` — вопросы к заказчику / решения, ожидающие согласования.
- `docs/07_acceptance_checklist.md` — контрольный лист спринта.
- `database/schema.sql`, `database/erd.mmd` — **проект** схемы БД, без исполнения миграций.
- `mockups/index.html` — автономный интерактивный макет четырёх экранов. Не проводит расчёты и не сохраняет данные.
- `frontend` — каркас React + TypeScript + Tailwind CSS (Vite). Содержит экраны-заглушки, без бизнес-логики.
- `backend/UrbanSketch.Financial.Api` — каркас ASP.NET Core с эндпоинтом `/api/health`. Без БД и CRUD.
- `infrastructure/docker-compose.yml` — конфигурация локального PostgreSQL для следующего этапа.
- `tests/reference_case.py` — эталон тестовых чисел из ТЗ (НЕ код модуля).

## Быстрый просмотр макетов (без установки зависимостей)

Откройте `mockups/index.html` в браузере. Кнопки навигации переключают четыре макета.

## Frontend

Требуется Node.js 22+ и npm. Из каталога `frontend`:

```bash
npm install
npm run dev
```

Откройте адрес, указанный Vite (по умолчанию `http://localhost:5173`).

## Backend

Требуется .NET SDK 10 (версия предварительная и подлежит согласованию). Из каталога `backend/UrbanSketch.Financial.Api`:

```bash
dotnet restore
dotnet run
```

Эндпоинт проверки: `GET /api/health`. Реальных расчётов и базы данных на этом этапе нет.

## PostgreSQL

Требуется Docker с Compose. Создайте `.env` рядом с `infrastructure/docker-compose.yml` по образцу `.env.example` и замените пароль. Затем:

```bash
cd infrastructure
docker compose up -d
```

Это лишь подготовка среды; таблицы/миграции создаются во втором спринте. Базу не публикуйте наружу в production.

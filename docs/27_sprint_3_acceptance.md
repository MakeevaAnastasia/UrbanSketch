## Реализация, API и миграции

- Пользовательские строительные площади хранятся в финансовой модели. Приоритет имеет заданное переопределение, включая ноль, затем исходная строительная площадь концепции. Если обе отсутствуют, строительная площадь остаётся неизвестной. Выручка берёт реализуемые площади концепции.
- `FinancialCalculationService` рассчитывает детализацию затрат, выручки и пять итогов на backend. C# `decimal` и проверки точности выявляют переполнение и потерю значащих дробных разрядов. ROI равен прибыли, делённой на затраты, а рентабельность продаж — прибыли, делённой на выручку. Оба отношения умножаются на 100. При нулевом знаменателе соответствующий коэффициент равен `null`.
- Backend сохраняет пять итогов, JSON-снимок детализации и SHA-256 fingerprint. В fingerprint входят версия алгоритма, параметры модели и ТЭП, используемые расчётом. Числа канонизируются независимо от локали и конечных нулей. PostgreSQL POST читает и блокирует концепцию, затем модель через `FOR UPDATE NOWAIT` и сохраняет итог в общей транзакции.
- React выбирает модель, запрашивает её результат и форматирует точные десятичные строки. Денежные суммы отображаются с точностью до копейки, проценты — с двумя знаками. Формулы выполняет сервер.

| Маршрут | Назначение |
| --- | --- |
| `POST /api/financial-models/{id}/calculate` | Пересчитать из сохранённых входов и записать полный результат, представимый в текущей схеме. Запрос без тела. |
| `GET /api/financial-models/{id}/calculation` | Получить сохранённый результат и проверить его актуальность по fingerprint. |

| Состояние | Поведение API и React |
| --- | --- |
| `not_calculated` | GET 200 при отсутствии снимка или fingerprint. React предлагает первый расчёт. |
| `current` | POST 200 после успешного сохранения или GET 200 при совпадении fingerprint. React показывает пять итогов и детализацию. |
| `stale` | GET 200 при различии fingerprint. API скрывает старый результат, включая итоги в прежних CRUD-ответах. React предлагает пересчёт. |
| `incomplete` | POST 200 при отсутствующей строительной площади. Доступны известные компоненты и список недостающих полей. Частичный результат доступен в ответе POST. |
| `error` | POST 422 при ошибке арифметики или ограничении хранения. Снимок и итоги сохраняют прежние значения. React показывает сообщение об ошибке. |

HTTP 409 возвращается при подтверждённом конфликте конкурентного доступа. React предлагает повторить расчёт. В PostgreSQL отдельно удерживали блокировку строки модели и строки концепции. Оба POST вернули 409. Следующий GET определяет актуальность по сохранённому снимку и текущим входам.

Миграции EF Core:

1. `20261111075406_InitialCreate` — исходная схема проекта, концепций, моделей и потоков.
2. `20261124065820_AddFinancialModelConstructionAreaOverrides` — два поля пользовательских строительных площадей.
3. `20261124075506_AddSavedFinancialCalculations` — fingerprint и JSON-снимок.

`dotnet ef migrations has-pending-model-changes` подтвердил соответствие модели snapshot. Список EF из трёх миграций совпал с реальной историей основной базы. Все три миграции отдельно применены с нуля в изолированной базе.

## Дефекты, ограничения и заключение

Дефектов реализации, потребовавших правки кода, по итогам приёмки не выявлено. При настройке изолированной среды штатный seed отклонил тестовое подключение своим ограничением на имя базы и порт. В отдельный контейнер загружены данные из штатного демонстрационного JSON через SQL. Первая попытка загрузки была отклонена из-за имён столбцов площадей и откатилась. После сверки с исходной миграцией тестовые данные загружены, PostgreSQL API и браузерные сценарии прошли.

Первая попытка SQL-сверки основной базы через stdin PowerShell не вернула JSON. Сверка завершилась после передачи той же read-only команды непосредственно в контейнер с проверкой результата и числовых токенов. При первом применении миграций в пустой тестовой базе EF сообщил об отсутствии таблицы истории на предварительном чтении, затем создал её и успешно применил все миграции.

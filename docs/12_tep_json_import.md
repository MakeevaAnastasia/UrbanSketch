# Загрузка демонстрационных ТЭП из JSON

**Дата проверки:** 11 ноября 2026 года, Europe/Moscow.
**Спринт:** №2 «Данные и базовая функциональность».

## Цель и исходные данные

Реализован явный локальный импорт ТЭП в PostgreSQL через EF Core.
Он подготавливает данные проектов и концепций для будущего API.
Расчёты, финансовые модели и денежные потоки при импорте не создаются.

Файл `database/seed/concepts.json` содержит один объект проекта
«Демонстрационный жилой комплекс» и массив variants из двух концепций.
У проекта и вариантов стабильные Guid, соответственно заканчивающиеся
на 0100, 0101 и 0102. Полные идентификаторы находятся в JSON.

| Концепция | Реализуемое жильё, м² | Реализуемая коммерция, м² | Машино-места |
|---|---:|---:|---:|
| Концепция А | 1000 | 200 | 20 |
| Концепция Б | 900 | 300 | 25 |

Показатели А взяты из контрольного примера ТЗ. Показатели Б явно заданы
текущим заданием как демонстрационные; дополнительные сведения не придуманы.

## Структура и неизвестные значения

Имена JSON-полей используют camelCase. Корень: id, name, variants.
Каждый вариант содержит id, name, residentialArea, commercialArea,
parkingSpaces и необязательные ТЭП с именами из текущей C#-модели.
Импортёр принимает один проект с непустым массивом вариантов;
демонстрационный файл содержит ровно два.

Строительные площади constructionResidentialArea / constructionCommercialArea
и показатели residentsCount, buildingsCount, maxFloors, socialAreas,
preschoolPlaces, schoolPlaces неизвестны и явно указаны как null.
Их также можно не передавать: результатом будет null, а не 0.
Строительные площади не вычисляются из реализуемых. Условное равенство
площадей в финансовом контрольном примере не считается фактическим ТЭП.

Идентификаторы, названия, реализуемые площади и количество парковочных мест
обязательны. Отсутствующий обязательный показатель отклоняется без фиктивного
значения. Служебная дата создания проекта заполняется текущим UTC-временем
только при первой записи.

## Устройство и валидация

Код расположен в `backend/UrbanSketch.Financial.Api/Data/Seed`:

- TepSeedDocument.cs — DTO, отличающие отсутствие обязательного числа от нуля;
- TepSeedReader.cs — чтение System.Text.Json, полная проверка документа
  и преобразование в Project / ConceptVariant;
- AreaJsonConverter.cs — точное чтение площадей без промежуточного округления;
- TepSeedImporter.cs — ограничения окружения, транзакция и повторяемая запись;
- SeedImportException.cs — безопасные диагностические сообщения.

Отклоняются неверный корневой объект, null/пустой variants, null вместо варианта,
ошибки синтаксиса и типов, неизвестные или повторяющиеся JSON-поля,
пустые/отсутствующие имена, нулевой/отсутствующий Guid и повторяющиеся ID во всём
документе. Названия обрезаются по краям; нулевой символ PostgreSQL text запрещён.

Все количества и площади должны быть неотрицательными. Количества помещаются
в int. Площади должны точно представляться как numeric(18,2): не более 16 цифр
целой части и 2 значащих дробных разрядов. Дополнительные конечные нули разрешены.
Поддержана научная запись JSON, например 1e3. Исходный числовой токен проверяется
до decimal-преобразования, поэтому слишком малое число не превратится в ноль,
а лишние дробные знаки не будут округлены PostgreSQL. Защитные пределы числового
токена: 1024 символа, экспонента от −1000 до 1000.

Ошибки файла (отсутствие, доступ, чтение) имеют понятные сообщения.
Ошибки CLI не выводят строку подключения или исключение с секретами.

## Транзакция и повторная загрузка

Сначала валидируется весь файл. Затем открывается одна транзакция,
проверяются фактическое имя базы, применённая InitialCreate и отсутствие
ожидающих миграций. До записи выводятся безопасные счётчики четырёх таблиц.

Импорт использует стабильные ID. Существующие проекты и концепции пропускаются
без обновления имён, дат, площадей и других значений. Добавляются только
отсутствующие записи. Совпадение имени с другим ID не считается совпадением:
при ручной замене ID в файле будет создана отдельная запись.

Если ID концепции уже относится к другому проекту, импорт целиком отклоняется.
Одна SaveChanges и Commit сохраняют проект и варианты вместе. При исключении
до Commit транзакция откатывается. Пользовательские финансовые модели и их
параметры сервис не загружает для изменения и не перезаписывает.

Транзакционная advisory-блокировка PostgreSQL сериализует параллельные вызовы
этого импортёра; освобождается при Commit/Rollback. Она не блокирует произвольные
записи других будущих сервисов. Конфликт с ними должен завершаться отказом,
а не перезаписью данных. Для импорта используется отдельный DI scope без
других несохранённых изменений.

## Точная команда запуска

Из корня репозитория в PowerShell, с уже настроенными User Secrets и PostgreSQL:

```powershell
$seedPath = (Resolve-Path database/seed/concepts.json).Path
dotnet build backend/UrbanSketch.Financial.Api --configuration SeedReview
if ($LASTEXITCODE -ne 0) { throw 'Не удалось собрать backend' }

$previousAspnetEnvironment = $env:ASPNETCORE_ENVIRONMENT
$previousDotnetEnvironment = $env:DOTNET_ENVIRONMENT
try {
    $env:ASPNETCORE_ENVIRONMENT = 'Development'
    $env:DOTNET_ENVIRONMENT = 'Development'
    dotnet run --project backend/UrbanSketch.Financial.Api --configuration SeedReview --no-build --no-restore --no-launch-profile -- --seed-tep $seedPath
    if ($LASTEXITCODE -ne 0) { throw 'Импорт не завершён; проверьте диагностическое сообщение' }
}
finally {
    $env:ASPNETCORE_ENVIRONMENT = $previousAspnetEnvironment
    $env:DOTNET_ENVIRONMENT = $previousDotnetEnvironment
}
```

Абсолютный путь устраняет зависимость от рабочего каталога dotnet run.
SeedReview сохраняет сборку отдельно от работающего Debug backend.
Окружение меняется только в текущем процессе PowerShell и восстанавливается.

Режим --seed-tep не запускает HTTP-сервер и после импорта завершает процесс.
Обычный запуск приложения не выполняет импорт. Публичного endpoint импорта нет;
/api/health сохранён. Production и другие окружения отклоняются до получения
контекста. Дополнительно сервис допускает только loopback-хост, порт 5432
и базу urbansketch_financial. Для подключения используется существующий ключ
ConnectionStrings:DefaultConnection; секреты и пароли не менялись.

Коды выхода: 0 — успех, в том числе повторный пропуск; 1 — ошибка импорта;
2 — неверный синтаксис CLI.

## Проверки PostgreSQL и повторяемости

До записи подтверждены локальная urbansketch_financial на 127.0.0.1:5432,
PostgreSQL 17.11, InitialCreate и четыре пустые предметные таблицы.
Выполнены два последовательных запуска CLI:

1. Добавлено проектов: 1; концепций: 2; пропущено: 0.
2. Добавлено проектов: 0; концепций: 0; пропущено: 2.

После завершения CLI прямые SELECT PostgreSQL подтвердили значения таблицы
выше, связь обеих концепций с демонстрационным проектом, отсутствие нарушенных
project_id и NULL всех восьми необязательных показателей каждого варианта.

| Таблица | Итоговое количество |
|---|---:|
| projects | 1 |
| concept_variants | 2 |
| financial_models | 0 |
| cash_flows | 0 |
| __EFMigrationsHistory | 1 |

Для проверки жизненного цикла отдельно запущен backend на порту 5187:
/api/health ответил 200, экземпляр штатно остановлен и запущен снова.
Повторное чтение PostgreSQL подтвердило те же счётчики и NULL. Тестовый экземпляр
затем штатно завершён. Ранее работавший пользовательский backend не затрагивался.

## Автоматические проверки

В tests/UrbanSketch.Financial.SeedTests добавлен запускаемый консольный набор
проверок .NET без отдельного тестового фреймворка и нового провайдера БД.
Тестовый проект использует существующий EF Core Relational 10.0.15,
явно закреплённый для согласования версий с API.

```powershell
dotnet run --project tests/UrbanSketch.Financial.SeedTests --configuration SeedReview
```

Автономный режим выполняет **30 проверок**, не подключаясь к PostgreSQL.
Для локальной базы явно предусмотрены два режима (запускать из корня репозитория):

```powershell
# Только до первого успешного импорта, когда предметные таблицы пусты:
dotnet run --project tests/UrbanSketch.Financial.SeedTests --configuration SeedReview -- --database-before database/seed/concepts.json

# После загрузки демонстрационных данных:
dotnet run --project tests/UrbanSketch.Financial.SeedTests --configuration SeedReview -- --database-after database/seed/concepts.json
```

Первый режим проверил отсутствие частичной записи при невалидной второй концепции
и полный откат при намеренном исключении SavedChangesInterceptor после реального
INSERT, до Commit. После обоих тестов база оставалась пустой; DELETE не выполнялся.
Второй режим завершился **33 успешными проверками**: 30 автономных плюс отказ ID
другого проекта, два повторных импорта без дубликатов и сохранение существующих
ТЭП при изменённом входном JSON. Временные JSON тестов не содержали секретов.
Интеграционные режимы защищены проверкой локального адреса и целевой базы,
не создают/удаляют базы и не применяют миграции.

Сборка backend и тестового проекта: **0 ошибок, 0 предупреждений**.
Проверка EF has-pending-model-changes: изменений модели нет.
Независимый read-only обзор кода существенных замечаний не выявил.

В начале настройки тестового проекта сеть NuGet была недоступна; восстановление
выполнено из локального кэша. Затем устранено расхождение транзитивных версий EF
в тестовом проекте явной ссылкой на существующую версию 10.0.15. Финальные проверки
проходят без этих ошибок и предупреждений; зависимости backend не обновлялись.
Старый tests/reference_case.py не выполнен: в окружении доступен только WindowsApps
alias Python, рабочего интерпретатора нет. Проверки самого импорта выполнены на C#.

## Ограничения и готовность к API

Это локальная демонстрационная загрузка, не синхронизация с UrbanSketch.pro.
Существующие значения не обновляются из JSON. Строительные площади остаются
неизвестными, поэтому данные ещё не являются полным входом финансового расчёта.
Структура БД из четырёх таблиц и ранее описанные отличия от исторической схемы
из семи таблиц не менялись. Новые миграции, API и финансовые расчёты не добавлялись.

Демонстрационные данные **готовы для следующего этапа REST API получения проектов
и концепций**. На этом этапе такие endpoints ещё не реализованы.

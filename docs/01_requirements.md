# 01. Требования к минимальной версии и границы проекта
**Статус:** рабочая спецификация спринта 1; согласование с заказчиком требуется.

## Назначение
Веб-модуль предварительной финансовой оценки концепций застройки на основе технико-экономических показателей (ТЭП), подготовленных в UrbanSketch.pro или загруженных из тестового JSON.

## Целевая аудитория
Архитекторы, девелоперы и инвесторы. Приоритетная роль пользователя в первой версии — **на уточнение**.

## Обязательная функциональность минимальной версии (по исходному ТЗ)
1. Выбор проекта и варианта концепции; получение его ТЭП.
2. Ввод и изменение параметров строительства, продаж, земли, дополнительных затрат и срока.
3. Подсчёт стоимости строительства, дополнительных расходов, выручки и финансовых показателей.
4. Редактируемое годовое распределение затрат и поступлений; чистый и накопленный поток.
5. Сравнение минимум двух концепций по финансовым показателям.
6. Хранение параметров и результатов; повторное открытие и редактирование модели.
7. CSV-экспорт; график денежных потоков; проверки вводимых данных.

## Не входит в обязательную первую версию
- Полноценный бухгалтерский, налоговый или управленческий учёт.
- NPV, IRR, срок окупаемости.
- Помесячные денежные потоки, кредиты, налоги, динамическая индексация цен.
- Экспорт XLSX и PDF, сценарии оптимистичный/пессимистичный.
- Полноценная интеграция с рабочим API UrbanSketch.pro — ТЗ допускает JSON для учебной реализации.

## Границы первого спринта
Аналитика, договорённости, проект данных, макеты, запускаемые каркасы React и ASP.NET Core. **Не входят:** реализованные вычисления, настоящий CRUD/сохранение в PostgreSQL, интеграция с UrbanSketch.pro, экспорт CSV.

## Нефункциональные требования: рекомендации команды, на согласование
- Читаемые подписи полей, единицы измерения; сообщения об ошибках ввода.
- Удобство на desktop и tablet; необходимость полноценного mobile — уточнить.
- Разделение расчётной логики и интерфейса для модульного тестирования.
- Точный десятичный тип данных для денежных величин; защита от деления на ноль.
- Версионирование исходных параметров при повторном расчёте — желательно, но требование не утверждено.

## Изолированная проверка PostgreSQL

Создан отдельный контейнер `urbansketch-migration-check-fad8ffef6bdb` на том же образе PostgreSQL 17. Порт опубликован только на loopback: **127.0.0.1:32768**; имя тестовой базы — `urbansketch_migration_test`. Для этой временной среды использован trust-доступ, собственный тестовый пароль не создавался и не сохранялся. Настройки основного приложения не менялись.

Восстановление: `pg_restore --no-owner --no-privileges --exit-on-error` в пустую тестовую базу. Отключение восстановления владельцев/привилегий относится только к тестовой копии. Все данные четырёх таблиц до миграции **полностью совпали** с исходным снимком. История содержала только InitialCreate.

```powershell

```

Для процесса EF тестовое подключение явно передано через `ConnectionStrings__DefaultConnection`, затем временная переменная удалена. User Secrets оставлены без изменений. Соединение указывало на тестовый порт и тестовую базу, не на основную PostgreSQL.

Проверки непосредственно в тестовой PostgreSQL выполнены SQL-утверждениями с `ON_ERROR_STOP=1`:

## Возникшие проблемы

В начале Docker Engine был выключен, порт 5432 недоступен. Найден пользовательский путь Docker Desktop и выполнен запуск; контейнер проекта автоматически поднялся и стал healthy. Изменение схемы до этого не предпринималось.

При первой сверке строки подключения адаптер PowerShell для DbConnectionStringBuilder ошибочно трактовал присваивание свойства как ключ. Защитная проверка остановила этап до backup/изменения БД. Использован явный setter `set_ConnectionString`, после чего безопасная сверка Host/Port/Database и credentials подтвердила ожидаемый локальный контейнер. Реального расхождения подключения не было.

Блокировки сборки работающим backend и ошибки миграции не возникли. Конфигурация User Secrets, React, исходный JSON, код и существующие миграции в этой задаче не изменялись. Commit/push не выполнялись.

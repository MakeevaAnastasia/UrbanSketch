# Интеграция React с API проектов и концепций

**Завершение проверки:** 12 ноября 2026 года, Europe/Moscow.
**Спринт:** №2 «Данные и базовая функциональность».

## Цель и границы изменений

Экран «Исходные данные» получает проекты, концепции и подробные ТЭП
из существующего REST API. Сохранены React-приложение первого спринта,
боковая навигация, типографика, panel/grid-оформление и адаптивность.
Вместо статических карточек первого экрана добавлены выбор и реальные данные.
Остальные три экрана остаются прежними макетами, без расчётов и сохранения.

Backend, PostgreSQL, миграции, concepts.json и User Secrets на этом этапе
не изменялись. Финансовые модели и потоки frontend не создаёт.

## Proxy и конфигурация

В существующем frontend/vite.config.ts настроено:

```text
/api → http://localhost:5079
```

React обращается к относительным URL того же origin, например /api/projects.
Vite dev server проксирует их в ASP.NET Core. CORS в backend не добавлялся,
адрес backend не прописан в компонентах.

В frontend/.env.example показаны две необязательные настройки:

- VITE_API_BASE_URL=/api — публичный базовый URL клиентских запросов;
- API_PROXY_TARGET=http://localhost:5079 — серверная настройка dev proxy.

Значения по умолчанию работают без создания .env. При необходимости локальное
переопределение можно передать через окружение процесса или игнорируемый .env.local.
VITE_* попадает в клиентскую сборку и не должно содержать секретов.
API_PROXY_TARGET не передаёт строку подключения PostgreSQL браузеру.
После изменения env-настроек dev server следует перезапустить.

Dev proxy работает только в Vite development server. Для production-сборки
понадобится reverse proxy /api либо отдельно настроенный публичный API URL
и соответствующая политика доступа; Vite preview сам эту маршрутизацию не создаёт.

## Код и TypeScript-типы

Добавлены:

- src/api/types.ts — ProjectResponse, ConceptVariantSummaryResponse,
  ConceptVariantDetailResponse по реальным DTO backend;
- src/api/client.ts — getProjects(), getProject(id), getProjectVariants(projectId),
  getConceptDetails(conceptId), стандартный fetch и безопасный ApiError;
- src/hooks/useConceptSelection.ts — загрузка и единое состояние выбора;
- src/components/SourceDataScreen.tsx — существующий первый экран с селекторами,
  карточками ТЭП, загрузкой, пустыми состояниями и повтором запросов;
- src/formatTep.ts — формат чисел ru-RU и единиц измерения;
- src/vite-env.d.ts — типы окружения Vite;
- tests/api.test.mjs и tests/browser.integration.mjs — проверки без новых библиотек.

В src/main.tsx подключены хук и первый экран. Настроены proxy и npm-скрипты;
package-lock.json, зависимости и styles.css не менялись.

Guid и UTC-даты представлены строками, площади — number, количества — number,
неизвестные показатели — number | null. Summary содержит шесть полей,
detail — все 14 полей, включая id/projectId/name. any не используется.

Клиент проверяет ответ во время выполнения: JSON content-type и синтаксис,
обязательные поля, Guid, UTC-дату, конечные неотрицательные числа, целые количества,
nullable-показатели и отсутствие повторяющихся идентификаторов. Для запрошенной
записи проверяется совпадение id, для списка концепций — projectId.
Хук дополнительно проверяет принадлежность подробной концепции выбранному проекту.

HTTP 404/500 и другие ошибки HTTP не превращаются в []. Отдельно обрабатываются
ошибка сети и некорректный ответ; исходный текст внутренней ошибки сервера
или транспорта пользователю не показывается. Пустой/неверный идентификатор
отклоняется до fetch. AbortSignal передаётся запросам.

## Выбор проекта и концепции

При первом открытии приложения выполняется GET /api/projects. Проекты и их
названия поступают с API. Один проект выбирается автоматически; если проектов
несколько, сначала предлагается выбор. При отсутствии проектов отображается
«В базе пока нет проектов».

Выбор проекта запускает GET /api/projects/{id}/variants. Прежняя концепция
и подробные ТЭП немедленно сбрасываются. После загрузки автоматически выбирается
первый вариант из отсортированного backend списка; далее можно переключаться
вручную. Пустой список даёт «У выбранного проекта пока нет концепций».

Выбор концепции запускает GET /api/concepts/{id}. Для заголовка и карточек
используется успешный ответ именно текущей концепции. getProject(id) также
реализован и проверен как часть клиента; первый экран берёт метаданные проекта
из списка, не выполняя лишнего запроса того же объекта.

useConceptSelection вызывается в App, а не внутри условно монтируемого экрана.
Поэтому projectId и conceptVariantId доступны на уровне приложения и сохраняются
при переходах между четырьмя экранами. Будущая форма может получить их через props
из App. DOM, query string и localStorage не используются для передачи выбора.
После полного обновления страницы выбор загружается заново; сохранение выбора
между сессиями пока не требуется и не реализовано.

## ТЭП, null и единицы

Первый экран отображает все 11 числовых показателей detail DTO:

| Поле | Подпись/единица |
|---|---|
| residentialArea | Реализуемая жилая площадь, м² |
| commercialArea | Реализуемая коммерческая площадь, м² |
| constructionResidentialArea | Строительная жилая площадь, м² |
| constructionCommercialArea | Строительная коммерческая площадь, м² |
| parkingSpaces | Машино-места, шт. |
| residentsCount | Количество жителей, чел. |
| buildingsCount | Количество зданий, шт. |
| maxFloors | Максимальная этажность, эт. |
| socialAreas | Площадь социальных площадок, м² |
| preschoolPlaces | Места в ДОУ, мест |
| schoolPlaces | Места в СОУ, мест |

null отображается как «Нет данных», без подмены нулём. Настоящий 0 отображается
как 0 с единицей измерения. Строительные площади не подменяются реализуемыми.
Числа форматируются ru-RU с разделителями тысяч и до двух дробных разрядов.
Старые вымышленные значения количества зданий и этажности первого React-экрана
заменены фактическим отсутствием данных.

## Загрузка, ошибки и защита от устаревших ответов

Предусмотрены независимые загрузки проектов, концепций и ТЭП. Зависимый select
отключён, пока нет данных для выбора. Для ошибки есть сообщение и соответствующая
кнопка «Повторить загрузку …». Ошибка завершает состояние loading, а повтор
очищает ошибку и запускает новый запрос. Пустой список отличается от ошибки.

При переключении карточки прежней концепции скрываются сразу, до нового ответа.
Каждый эффект использует AbortController и флаг актуальности, при выборе
синхронно обновляются refs идентификаторов, а ресурс связан с ключом запроса.
Счётчики попыток поддерживают повторный выбор и быстрое переключение A → Б → A
в одном пакете событий. Даже транспорт, игнорирующий abort, не может заменить
текущие данные поздним ответом старого запроса.

## Команды запуска

Backend должен быть актуальной сборкой, работать в Development и использовать
уже настроенные User Secrets. Если на 5079 запущена старая сборка, её следует
вручную завершить и запустить актуальную. Из корня репозитория:

```powershell
dotnet run --project backend/UrbanSketch.Financial.Api --configuration FinancialReview --launch-profile http
```

Профиль http содержит localhost:5079 и ASPNETCORE_ENVIRONMENT=Development.
Если DOTNET_ENVIRONMENT явно задан иначе, согласовать его для текущего процесса
с Development, как описано в docs/13_projects_concepts_api.md. Глобальные
переменные Windows и секреты менять не требуется.

В другом терминале:

```powershell
cd frontend
npm.cmd run dev -- --port 5173 --strictPort
```

В Windows использован npm.cmd: вызов npm.ps1 заблокирован текущей execution policy.
Политика выполнения не менялась. На других системах используется обычный npm.
Если 5173 уже занят вашим Vite, использовать существующий экземпляр либо
перезапустить его вручную, а не запускать второй с незаметно изменённым портом.

Проверки из каталога frontend:

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
npm.cmd run test:browser
```

Браузерные проверки требуют работающий frontend/proxy и реальный демонстрационный
проект в API. Скрипт использует установленный Chrome headless с новым профилем,
а не пользовательскую сессию. BROWSER_BINARY позволяет указать другой совместимый
Chromium-браузер; FRONTEND_URL — иной локальный адрес frontend. Новые браузерные
или тестовые npm-пакеты не устанавливаются.

## Подготовка формы финансовых параметров

Общая пара selection.projectId / selection.conceptVariantId уже доступна в App
и не теряется при переключении экранов. Можно передать её будущей форме через
обычные props, без нового глобального хранилища. Финансовая форма, её сохранение,
запросы CRUD финансовых моделей, вычисления и сравнение остаются отдельными задачами.
После актуализации локального backend можно переходить к этому этапу;
в рамках текущей задачи он не начат.
